# 架构与行为边界

## 工程

- `crates/desktop`：GPUI Kit 0.9.1 原生窗口、六个中文页面、输入与文件选择，后台消息连接。
- `crates/core`：领域模型、平台契约、任务引擎、SQLite 存储、迁移和 profile 文件锁。不依赖窗口或具体平台。
- `crates/platforms`：chromiumoxide 浏览器会话、抖音、快手和小红书适配器，以及用于测试的模拟适配器。
- `migrations`：带版本记录的 SQLite 初始化迁移。
- `tests/fixtures`：本地上传与弹窗夹具，不含真实账号和凭据。

依赖方向为 desktop → core + platforms，platforms → core。Cargo.lock 固定完整依赖图，Rust 工具链固定在 rust-toolchain.toml。

## 界面与后台

GPUI 线程接收操作并绘制界面；后台专用线程持有 Tokio 运行时，操作存储并调度任务，通过消息传回快照与通知。浏览器启动、导航、等待和上传不在绘制线程执行。

chromiumoxide handler 在独立异步任务中持续轮询。浏览器会话正常关闭时发送关闭命令、等待进程，超时则终止自己创建的浏览器。取消时释放会话，chromiumoxide 的自有子进程使用 kill-on-drop。退出应用时取消后台工作并等待结束。强制结束整个应用进程后的浏览器残留回收尚未完成，不宣称 M3 已全量验收。

## 同网站多账号

账号使用随机 UUID 标识，昵称或别名不作为主键，因此同平台、相同昵称也能分别管理。每个账号独立 profile、独立文件锁和独立任务历史。

添加账号自动编号。登录时只提取昵称，不把完整用户资料、Cookie 或 token 返回到业务层。未自定义名称的账号随平台昵称更新；手动改名设置自定义标记，后续状态更新通过事务合并，保留用户的名称。旧数据有名称但没有新标记时按已自定义处理，避免覆盖。

抖音登录检查可通过创作者首页显示的账号信息确认会话，无需等待上传控件。发布准备遇到登录后跳转首页时，会重新进入上传页，再单独确认上传控件可用。

SQLite 部分唯一索引禁止同一账号存在两个活跃任务；profile 文件锁进一步防止登录与任务同时占用同一会话。桌面应用也对数据目录使用实例锁。当前全局并发为 1。

## 提交边界

创建批次使用唯一请求 key，重复点击返回同一批次。每个批次与账号最多一个 job。内容和素材元信息在入队时保存快照。

任务准备完成后设置独立的 `ready_to_submit` 标记。用户核对账号和作品标题后确认发布。平台适配器检查素材、编辑内容和发布控件，再执行提交。抖音要求短信验证时，应用展示官方验证步骤并等待用户操作。模拟适配器供自动化测试使用。

引擎在平台动作之前以事务保存 job 的 Submitting 和 attempt 的 submitting_at。取得明确的成功回执后记录为 Submitted。抖音回执需要作品编号。快手和小红书可以凭明确接收回执记录结果，作品编号由平台提供时才显示。未取得可靠结果时保留 Unknown，等待核对。Submitted 表示平台接收，公开状态由平台审核结果决定。

准备前停止为 Cancelled，最终提交后停止等待时保留 Unknown。用户可以从任务卡片打开对应平台的内容管理，核对后确认未发布。确认会把任务转为 Failed 并记录人工核对结果，之后可手动重新准备。每次 claim 新建 attempt，原执行记录继续保留。

## 当前平台能力

| 能力 | 抖音 | 快手 | 小红书 |
| --- | --- | --- | --- |
| 独立账号会话 | 应用内扫码，真实会话已验 | 应用内扫码，真实会话已验 | 应用内扫码或短信，真实登录待验 |
| 视频发布 | 已验证真实发布 | 已验证真实发布 | 本地测试通过，真实发布待验 |
| 图文发布 | 本地测试通过，真实发布待验 | 本地测试通过，真实发布待验 | 本地测试通过，真实发布待验 |
| 标签 | 以描述中的话题文本填写 | 以描述中的话题文本填写 | 以正文中的话题文本填写 |
| 停在最终提交前 | 支持 | 支持 | 支持 |
| 提交结果 | 依据本次平台回执 | 依据本次平台回执 | 依据本次平台回执 |
| 视频自定义封面 | 竖版和横版分别选填，提交前复核 | 尚未支持 | 尚未支持 |
| 排期 | 尚未支持 | 尚未支持 | 尚未支持 |

平台页面变化、登录超时、上传失败、文件变化与浏览器断线会给出对应的有限诊断。不会把平台原始响应或可能含会话信息的浏览器错误直接写到用户日志。
